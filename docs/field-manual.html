A cognitive-manipulation x-ray — on-device

The brain map is a worse detector than the text.

That one finding — proven by the project's own experiment — is why this system looks the way it does. Highlight text, press ⌘B, and a local LLM names the persuasion technique. A brain model shows only where in cortex the words land. This manual walks the whole arc: the premise, the experiments that overturned it, the two algorithms, the engineering, and what's still open.

Module 00 Orientation

One idea holds the whole system up

Every file's docstring repeats the same sentence, so start here: detection and interpretation are done by two different models, because each is only good at one job.

DetectionLocal Llama-3.2-3B (4-bit MLX) names the technique + a calibrated confidence. This is the verdict.
+
InterpretationTRIBE v2 (Meta fMRI model) shows where in cortex the text lands. Never a detector.

The two are decoupled behind a Swift Classifier protocol talking to a local FastAPI server: POST /classify (fast, ~2–3s) and POST /brainmap (slow, opt-in, ~15s–2min). Two OS processes cooperate — the 🧠 menu-bar app you press ⌘B in, and a headless server that holds the models, kept alive 24/7 by a launchd agent on port 8765.

Why this matters up front

Almost every design decision downstream — which model runs when, what the UI is allowed to claim, why the brain map is opt-in — falls out of this split. Hold onto it.

Check yourself — why two processes instead of one app?
The models are heavy (a resident detector + an on-demand 7 GB brain model). Keeping them in a separate long-lived server means the tiny menu-bar app can be rebuilt, relaunched, or crash without paying model-load time again — and the server stays warm across sessions. The app just sends JSON to 127.0.0.1:8765.
Module 01 Origins

The thesis that died

The project (2026-06-28) began with a bolder, cleaner idea than the one that shipped. The plan: highlight text → feed it to TRIBE v2 as the classifier → read which brain region "lit up" → map that region to a persuasion tactic through a hand-authored table:

fear → amygdala dopamine bait → nucleus accumbens outrage → anterior cingulate reasoning load → prefrontal cortex

It was seductive because it sounded like real neuroscience and it used TRIBE's headline capability directly — "no LLM needed for the core." The overlay would announce not just the tactic but the brain structure it targets.

Foreshadow

Two assumptions were load-bearing and both were untested: (1) that emotions map to distinct brain regions, and (2) that a brain model derived from text could detect better than the text itself. Module 2 tests both — and demolishes them.

A5 is the hinge — and it's a theorem, not a fluke

The brain map is computed as text → Llama embedding → brain projection. So the predicted brain response is a function of the text: brain = f(text). The data-processing inequality says a transformation can never add information — so a classifier reading the brain map can never beat one reading the text it was derived from. A5 confirmed it empirically: 100% vs 75%. That killed "TRIBE-as-detector" and forced the hybrid split from Module 0.

The pivot, in one line

Detection is the LLM's job. The brain map's only legitimate value is visceral interpretation — "here is where it lands in your cortex" — never accuracy. Everything the UI says obeys this.

Why these test cases are trustworthy

  • Length-matched sentences so sentence length can't fake a difference.
  • Per-vertex z-scoring across sentences removes each vertex's baseline, so a region can't look "active" just because it's always active.
  • Held-out sentences in I1b (none from the 30 baseline sentences) — no leakage.
  • A neutral baseline to z-score against (Module 4) — an emotional baseline would cancel the very signal you want.
  • Cohen's d, not just p — effect size, so "significant but tiny" can't masquerade as a real signal.

Check yourself — why was A4 (TF-IDF) called "uninformative" even though it lost?
Because it lost for the wrong reason. Bag-of-words can only match exact vocabulary it saw in training, so on unseen test sentences it fails regardless of whether the brain map is good. It doesn't isolate the thing being tested. A5 fixed this by using the same Llama embedding TRIBE is built on as the control — a fair fight — which is why A5, not A4, is the decisive experiment.
Module 03 Detection

How the LLM actually names the technique

The obvious approach — ask the model "which technique is this, and how confident are you?" — was tried and rejected. Free-form generation did two bad things: it collapsed distinct techniques (dopamine-bait and social-proof both got written as false-urgency), and it emitted a constant "80" for confidence every time — a verbal tic, not a probability.

The method: label log-prob scoring

Instead of letting the model write a label, the server scores how likely each candidate label is under the frozen model, then turns those scores into a probability distribution. Concretely, for every one of 12 labels:

  1. Build a chat prompt that lists all techniques + definitions and ends "answer with the technique name only."
  2. Append the candidate label and run one forward pass to get the model's log-probability of the label's tokens (teacher-forced next-token log-probs).
  3. Length-normalise — divide by the number of label tokens so a long name like critical-thinking-suppression isn't penalised for being long.
  4. Softmax over the 12 scores → argmax is the verdict; the winner's share is the confidence.
The confidence knob: temperature < 1

With 12 candidates, a raw softmax spreads probability thin — an obvious false-urgency landed at only ~20%, which reads as "unsure" even when the model isn't. So each score is divided by CONFIDENCE_TEMP = 0.25 before exponentiating. Temperature below 1 exaggerates the gaps, pushing a clear winner toward an assertive number. Same urgency example: 20% → 97%. Genuine ties stay honest (hype / awe / urgency can still land ~34% three-way).

The 12-label set

Eight original negative-valence techniques, three positive-valence ones added later (excitement/hype can manipulate too), plus none for neutral text.

fear-mongering critical-thinking-suppression tribal-in-group-bias dopamine-bait outrage authority-appeal false-urgency social-proof-conformity hype-hope-mongering fomo manufactured-awe none
The trade-off logged

Going from 8 to 12 labels dilutes per-label confidence — the small 3B model separates the positive-valence trio only weakly. The temperature sharpening mitigates it; genuine model ties are left honest rather than faked.

Check yourself — why score labels instead of generating one?
Scoring gives you a closed set (the model can only pick from the 12 real techniques — no drift into invented labels) and a genuine probability for each, because you read the model's own log-probabilities rather than a number it made up. Generation gave neither: it drifted between labels and its "confidence" was a constant. The whole "confidence is mandatory" rule depends on this.
Making it instant

Scoring 12 labels naively meant 12 forward passes, each re-reading the whole ~350-token prompt — about 4 seconds per ⌘B. The fix: process the shared prompt once into a KV cache, then let each label continue from that cached state. Same verdicts, ~450ms — a 9× speedup that's what makes ⌘B feel instant.

The false-positive trap → a two-stage gate

Highlighting a Google AI Overview's friendly "Hello! How can I help you today?" reported "Hype 84%". The reason is structural: a single 12-way classifier must pick a label, so it forces benign, upbeat, or helpful text toward its nearest tactic. Worse, every prompt tweak just slid the whole none/manipulation boundary — fix greetings and you start missing real manipulation.

The fix is to split the decision. Stage 1 is a clean yes/no gate — "is this actually trying to persuade or manipulate?" — where benign text (greetings, questions, requests, plain facts, reviews) answers no and becomes none. Stage 2, the unchanged 12-way technique classifier, runs only if the gate says yes. The line is drawn by intent: "the sale ends Friday" is ordinary; "hurry, the sale ends Friday, don't miss out!" is manipulation.

Why two stages, not a better prompt

A binary gate is a far easier, cleaner decision than diluting "none" across a 12-way softmax. Tuned against a realistic mix (60% benign — how people actually highlight), it now catches 20/20 manipulation while correctly ignoring 27/30 benign lines. The one honest cost: a second short model pass (~450ms → ~650ms).

Module 04 Interpretation

The brain map, honestly rendered

Deep-scan is opt-in (the 🧠 menu) because it's slow. When you trigger it, the server turns your sentence into a predicted fMRI cortical response and reduces it to something a human can read. Five moves:

1 · Text → cortex

TRIBE v2 predicts activation on 20,484 fsaverage5 cortical vertices. In the default text-only mode there's no speech synthesis at all: the sentence is split into synthetic Word events at 0.35s each and fed straight in. Because word events already exist, TRIBE's transcription step early-returns — "that early-return is the whole trick." No TTS, no WhisperX, no audio dependencies.

2 · Subtract "normal"

Raw activation is dominated by "there is language here" (auditory cortex — model-intrinsic, per I1). To find what's content-driven, each vertex is z-scored against a neutral baseline: z = (activation − mean) / std, where mean/std come from 30 deliberately neutral, factual sentences.

Learned the hard way

The baseline must be neutral text. If it contained emotional sentences, z-scoring would subtract the emotional signal too — leaving only sensorimotor noise. The baseline is also tagged with its mode; the server refuses to serve if a text baseline is paired with an audio pipeline.

3 · Keep only the honest regions

Ranking all regions of a single sentence surfaces low-level acoustic/sensorimotor cortex — an artifact, not meaning. So the profile reports only a curated set of value- and language-evaluation ROIs (inferior-frontal, orbital, vmPFC), the ones A7 proved separate emotional from neutral at d=0.95. Those group into three readable systems:

Valueorbitofrontal — is this worth wanting?
Languageinferior-frontal — parsing the claim
ExecutivedlPFC — cognitive load / control
high (z ≥ 0.5) elevated (≥ 0.15) low below baseline (≤ −0.15)
4 · Say only what's true

TRIBE is cortex-only — it cannot see the amygdala or nucleus accumbens. So the UI never says "fires your fear center." It says "engages your value / language-evaluation cortex." The response even carries a caveat field restating this. This is Module 1's dead thesis, buried properly.

5 · Give the memory back

TRIBE carries its own ~7 GB text encoder; co-loaded with the detector that's ~13 GB on a 24 GB Mac — swap-thrash territory. So TRIBE is loaded and freed on every call, leaving only the light 4-bit detector resident. And if swap is already >90% full, /brainmap refuses rather than thrashing the disk.

Check yourself — why z-score against neutral instead of showing raw activation?
Because raw activation for any sentence is dominated by the model's built-in "this is speech/language" response — the same for a grocery list and a threat. Subtracting the neutral baseline cancels that shared component, so what's left is the part that's specific to this content. Without it, every sentence would look like a lit-up auditory cortex and tell you nothing.
Module 05 Engineering

Making it real, and invisible

The science is half the work. The other half is a background macOS agent that reads any app's selection, never steals focus, survives its own rebuilds, and doesn't melt a 24 GB laptop. The hard-won lessons:

Capture: the Accessibility → pasteboard pivot

The first build read selected text via the Accessibility API — which returns empty for Chrome/Safari article bodies and PDFs. The fix: synthesize a ⌘C, read the clipboard, then restore the previous clipboard so the user never notices. That reads text everywhere. ⌘B is a deliberately non-consuming global hotkey, so it still bolds in editors while also triggering a scan.

The signing saga (why ⌘B kept dying)

macOS ties the Accessibility permission to the app's code signature. With ad-hoc signing, every rebuild produced a new signature — silently revoking the grant and breaking ⌘B. The fix was a persistent self-signed identity ("CPD Local Signing") so the signature — and therefore the permission — is stable across rebuilds. A one-time re-grant, then it sticks.

The four-hour freeze

num_workers deadlock

The baseline build froze at 2/30 sentences, 0% CPU, for hours. Cause: TRIBE's checkpoint resets its DataLoader to ~20 forked worker processes at load time, and forked workers deadlock on macOS. Patching the source wasn't enough — "the checkpoint wins." The fix, harden_tribe(model), forces num_workers = 0 after every load, plus per-sentence checkpointing so a hang costs one sentence, not the whole run.

Two Metal workloads, one GPU

MLX's GPU streams are thread-local, so all detector work is pinned to one dedicated server thread. And an isBusy mutex in the app serialises classify vs. deep-scan, so an MLX detection and a PyTorch brain-map never fight over Metal at once.

Module 06 Privacy

A tool that defends your mind can't spy on it

Everything runs on-device — no cloud, no API keys, no telemetry. Two guardrails enforce it:

  • The gTTS leak, closed. An early TTS step used Google's gTTS, which uploaded every highlighted snippet to Google's servers. It was replaced with offline macOS say + ffmpeg (and the default text-only path skips TTS entirely). Bonus: 75s → 22s per sentence.
  • Secrets never get classified. Before any text is sent, SensitiveText screens it for passwords, API-key prefixes (sk-, ghp_, hf_…), JWT shapes, and card-number patterns — and skips them. Analysing a secret is pointless and a liability, even locally.

Module 07 Frontier

What's unresolved

Two threads are deliberately left open, and it's worth knowing why.

Capture Region (OCR) — broken, being chipped at

The 🧠 menu's "Capture Region" — drag-select a screen area → screenshot → Vision OCR → classify — doesn't yet produce a verdict. The silent no-op was fixed (every branch now shows an on-screen notice and jumps to the Screen-Recording settings pane), but whether the full OCR→verdict path works once permission is granted is still unconfirmed. Suspects: the Screen-Recording grant or the ScreenCaptureKit / Vision step.

Subcortical "Track B" — deferred on purpose

Why it stays parked

Training TRIBE to see the amygdala + nucleus accumbens is scientifically motivated but blocked by cost: no auto-download, fMRIPrep derivatives not shipped (GPU-weeks of preprocessing), a cortex-only released checkpoint, Slurm-based training — and decisively, it would improve interpretation only, which A5 already showed is not where accuracy comes from.

Also open, undecided: a confidence-calibration study, a browser extension, and a vision-LLM for images. The positive-valence confidence dilution from Module 3 remains a known, honestly-surfaced limitation.

Module 08 Testing

How we actually know it works

This is the honest accounting the manual was started for. There were two different questions inside "does it work" — and the second one now has a much better answer than it used to.

On self-authored data~80% — and misleading. When you write the test examples and tune the model to them, the score measures memorization, not generalization.
On external data~45%. Measured on 300 independently-labeled examples across 6 vectors (dark-patterns + fallacy + clickbait) we never authored or tuned on. A ~35-point overfitting gap — the honest number.

This is the most important lesson in the manual. The self-authored benchmarks (the ones that drove the manufactured-awe fix and the two-stage gate) were real progress, but they flattered the system — because the same person wrote the examples and tuned the prompts. Only an external, never-tuned-on test set tells the truth, and it's humbling.

What the honest metrics reveal

The gate ranks well but is set too tight. Gate PR-AUC is 0.91 — it can separate manipulation from benign — but at the shipped threshold it misses ~41% of real manipulation (tuned on easy examples). The confidence % lies. Calibration error is 0.37: on the cases where it says "99%", it's right ~60% of the time — badly over-confident, because the temperature was tuned for assertiveness, not honesty. Tactic labels blur in the urgency/fomo cluster.

The right response isn't to hide these numbers — it's to measure them properly: macro-F1 and per-class scores (not accuracy) under class imbalance, Wilson/bootstrap confidence intervals (N is small, so ±6–14 points), PR-AUC for the gate, and ECE for the confidence. That's what bench_full.py now does, and what docs/BENCHMARKING.md lays out as the roadmap.

…and then fixed what it exposed

The honest metrics pointed at three concrete fixes, each validated on a held-out external half: (1) the gate's probability had been saturated by the assertiveness temperature, so un-sharpening it made the ranking usable (PR-AUC 0.93) and the threshold tunable; (2) the confidence was over-confident, so Platt calibration now maps the shown % to P(correct) — ECE 0.37 → 0.10; (3) when a technique label is genuinely unclear, the card now abstains ("treat the label as a guess") instead of asserting it; and (4) the biggest technique blur — scarcity read as time-urgency — was fixed by splitting fomo (scarcity/miss-out) from false-urgency (the clock), lifting fomo recall 0.05 → 0.70. (Contextual calibration was also evaluated — no gain, since the yes/no gate already avoids the priming it targets.) The point isn't that it's fixed — it's that honest measurement is what tells you what to fix.

The takeaway for anyone learning this system: be suspicious of any benchmark whose author also tuned the model on it. The idea is proven by experiment; the detector works in the "is this manipulation at all?" sense; but the precise accuracy is lower and the confidence less trustworthy than a demo suggests — and saying so plainly is the point.
